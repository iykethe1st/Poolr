## Overview
Implement the platform fee model for Poolr. Fees are charged as a flat amount on each individual contribution at payment time - not as a percentage on the payout. This ensures the platform reserve starts building from the very first contribution in cycle 1, before any payout has gone out, which is when the reserve is needed most.

## Why contribution-based fees, not payout-based
If Poolr charged a fee only on payouts, the reserve would be empty during the early cycles of every group - exactly when a default is most damaging. A contribution-based fee means reserve accumulation is proportional to risk exposure from day one. It also distributes the cost across all contributing members rather than concentrating it on the payout recipient.

## Fee structure

### Flat fee tiers (configurable via environment variables)
| Contribution amount | Platform fee |
|---|---|
| Under NGN 10,000 | NGN 100 flat |
| NGN 10,000 - NGN 50,000 | NGN 200 flat |
| Above NGN 50,000 | NGN 400 flat |

### Fee split
- 20% of every fee collected goes to the platform protection reserve
- 80% goes to Poolr operating revenue
- Example: NGN 200 fee on a NGN 20,000 contribution - NGN 40 to reserve, NGN 160 to revenue

### What the member pays
- Paystack path: member pays `contribution_amount + fee_amount` in a single Paystack transaction
- Wallet path: wallet is debited `contribution_amount + fee_amount` in a single operation
- The fee is shown clearly to the member before they confirm payment

## Schema changes

### New `ContributionFee` table
Tracks every fee collected at contribution time.
```
ContributionFee {
  id               uuid PK
  contribution_id  uuid FK -> Contribution  UNIQUE
  user_id          uuid FK -> User
  contribution_amount int    -- the contribution amount in kobo
  fee_amount          int    -- total platform fee charged in kobo
  reserve_amount      int    -- 20% of fee_amount (deposited to reserve)
  revenue_amount      int    -- 80% of fee_amount (operating revenue)
  created_at          timestamp
}
```

### Update `Contribution` model
- Add `fee_amount` (int) -- the platform fee charged for this contribution, stored for quick reference without joining ContributionFee
- Add `total_charged` (int) -- contribution_amount + fee_amount (what Paystack actually charged or what was debited from wallet)

## Acceptance criteria
- Fee is collected at contribution time, never at payout time
- Paystack checkout amount equals `contribution_amount + fee_amount` exactly
- `FeeService.collectFee()` and contribution PAID status update are always atomic - no contribution can be marked PAID without a corresponding `ContributionFee` record
- A duplicate `charge.success` webhook for the same contribution does NOT create a second `ContributionFee` record (idempotent)
- Wallet-funded contributions also collect the fee - no fee-free path exists
- `can-pay` wallet check accounts for the fee amount
- All fee configuration is changeable without a code deploy
- Payout processor sends full amount to recipient with zero deduction
- Admin can view total revenue and reserve contributions from fee collection
